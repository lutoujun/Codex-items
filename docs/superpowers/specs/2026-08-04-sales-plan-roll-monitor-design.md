# 月滚动销售计划监控与入库设计

## 目标

为 `ads_dss_sales_plan_roll_msku_info.sh` 补充前置监控：仅当 `jamf_dis.upload_dss_sales_plan_roll_info` 在 `upload_month = do_month` 下已上传 10 个去重店铺时，才执行原有三步 `SQL_QUERY`。一个 `do_month` 的计划版本只允许成功入库一次。

## 输入与口径

- 复用原脚本上方的 `do_month`：脚本参数传入日期时按该日期计算，否则按美西运行日计算。
- 已上传店铺数：`count(distinct plan_shop_code)`，忽略空店铺编码。
- 达标阈值：10 家；大于 10 家同样视为达标，避免数据补传导致流程永久等待。
- 本月版本：`jamf_ads.ads_dss_sales_plan_roll_msku_info.version_no = do_month`。

## 处理流程

1. 获取进程级 `flock` 锁，阻止同一脚本并发执行。
2. 查询目标 ADS 表是否已有 `version_no = do_month` 的记录。存在时打印幂等跳过信息并正常退出。
3. 查询上传表的去重店铺数及排序后的店铺列表。
4. 若不足 10 家，打印当前数量和店铺列表后正常退出，供下次调度继续等待。
5. 达标时执行原脚本的完整 `SQL_QUERY`（原有三步：单价、下月模板、当月版本）。任一 SQL 失败立即退出。
6. SQL 成功后，复查 ADS 表存在本月版本记录；为空则失败退出，避免将未实际落库的版本标记为完成。

## 幂等与边界

- 幂等主判定是已存在的本月 `version_no`；文件锁只作为并发窗口防护。
- 该方案假定单个调度节点执行脚本。若存在多机并发，需要增加数据库锁表或调度系统单实例策略。
- 上传店铺少于 10 家不是任务故障，因此退出码为 0；真正的 SQL 或版本复查异常使用非 0。
- 店铺列表仅用于日志审计，使用单行逗号分隔输出。

## 验证场景

- 已有本月版本：SQL 不执行。
- 上传 0 至 9 家：输出数量和店铺列表，SQL 不执行。
- 上传至少 10 家且 SQL 成功：复查 ADS 表存在 `version_no = do_month` 的记录。
- SQL 失败：脚本失败退出。
- SQL 成功但版本复查为空：失败退出。
